# Architecture Decision Record: Padnakasht Storefront

## گزینه‌های بررسی‌شده

| مسیر | هزینه پایه | مزیت | محدودیت تعیین‌کننده | تصمیم |
|---|---|---|---|---|
| Cloudflare Workers + Supabase Free | رایگان در سهمیه‌ها | Worker برای سایت و API، دیتابیس و Edge Function موجود، بدون اعتبار AI | Supabase Free در بی‌فعالیتی ممکن است متوقف شود؛ Cron برای کاهش این ریسک اضافه شده | **انتخاب شد** |
| Cloudflare Workers + D1 | رایگان در سهمیه‌ها | دیتابیس نزدیک به Worker و بدون سرویس ثالث | نیاز به ساخت D1 و دریافت شناسه از داشبورد؛ پروژه D1 آماده در حساب در دسترس نبود | گزینه جایگزین |
| GitHub Pages + Supabase | رایگان در سهمیه‌ها | میزبانی استاتیک ساده | برای پراکسی امن، کوکی HttpOnly و Cron به سرویس دیگری نیاز دارد | رد شد |
| Vercel + Supabase | طرح رایگان با محدودیت | استقرار Git محور و امکانات توسعه | مزیت عملی نسبت به Cloudflare ندارد؛ شرایط استفاده و محدودیت‌های طرح رایگان باید برای فروشگاه تجاری جداگانه بررسی شود | انتخاب نشد |
| CMSهای میزبانی‌شده مانند Wix، WordPress و Webflow | رایگان یا پولی، بسته به ارائه‌دهنده | مدیریت بصری و آماده | محدودیت طرح رایگان، افزونه‌ها، برندینگ یا نیاز به میزبانی/پرداخت جداگانه | انتخاب نشد |

## تصمیم نهایی

از پروژه Supabase موجود پادناکِشت استفاده می‌شود؛ پروژه جدید یا پلن پولی ساخته نشده است. Cloudflare Worker فایل‌های سایت را ارائه می‌کند و API را به Edge Function متصل می‌کند. سه بار در روز، Worker تابع سلامت را اجرا می‌کند تا فعالیت دیتابیس ثبت شود و احتمال توقف خودکار طرح رایگان کاهش یابد. این کار تضمین قراردادی برای جلوگیری از توقف Supabase نیست.

کلید publishable در تنظیمات عمومی Worker قرار دارد. کلید service-role فقط در محیط Supabase استفاده می‌شود. گذرواژه مدیر به‌صورت هش PBKDF2 در دیتابیس ذخیره می‌شود و نشست مدیر با HMAC امضا می‌شود.

## هشت مسیر عملیاتی

1. رابط فروشگاه فارسی، راست‌چین و واکنش‌گرا
2. فهرست کالاها، دسته‌بندی و مدیریت تصویر
3. سبد خرید و مقدارهای نیم‌کیلوگرمی
4. ثبت درخواست خرید با اعتبارسنجی اطلاعات مشتری
5. پیگیری سفارش با کد و شماره تماس
6. راه‌اندازی یک‌باره مدیر و ورود با نشست HttpOnly
7. مدیریت قیمت، موجودی، وضعیت سفارش و هزینه ارسال
8. کنترل امنیت، محدودسازی درخواست، ثبت رویداد و رزرو/بازگردانی تراکنشی موجودی

## ده بازبینی مستقل خودکار

هر بازبینی در یک Job جداگانه GitHub Actions اجرا می‌شود:
1. معماری و مرزبندی سرویس‌ها
2. امنیت و احراز هویت
3. ساختار و دسترسی پایگاه داده
4. قراردادهای ثبت و پیگیری سفارش
5. صحت رزرو و بازگردانی موجودی
6. دسترس‌پذیری فرم‌ها و ساختار فارسی
7. واکنش‌گرایی موبایل و کاهش حرکت
8. منشأ و شفافیت تصاویر
9. عملکرد و هدرهای امنیتی
10. تنظیمات استقرار و سهمیه رایگان

شاخه \`website-release\` فقط پس از موفقیت آزمون ساخت، بررسی TypeScript و هر ده Job بازبینی به‌روزرسانی می‌شود. Cloudflare باید فقط همین شاخه را منتشر کند.

## مرزهای نسخه فعلی

- درگاه پرداخت آنلاین وجود ندارد.
- قیمت‌ها و موجودی‌های تاریخی تأییدنشده‌اند و به مشتری نمایش داده نمی‌شوند.
- عکس‌های فعلی نمایشی‌اند، نه عکس اختصاصی محصولات یا بسته‌بندی پادناکِشت.
- دسترسی به Cloudflare و Supabase از ایران ممکن است به VPN یا محدودیت‌های منطقه‌ای وابسته باشد و باید از شبکه کاربر آزمایش شود.
