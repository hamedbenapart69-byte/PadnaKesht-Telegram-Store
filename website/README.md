# فروشگاه اینترنتی پادناکِشت

فروشگاه مستقل فارسی و راست‌چین با کاتالوگ محصولات، سبد خرید، ثبت درخواست سفارش، پیگیری سفارش و پنل مدیریت.

## زیرساخت انتخاب‌شده
- **Cloudflare Workers + Workers Static Assets** برای میزبانی سایت و پراکسی API
- **Supabase Free** برای پایگاه داده و Edge Function ثبت سفارش
- GitHub فقط برای نگهداری سورس و اتصال خودکار استقرار؛ هیچ هزینه یا اعتبار AI مصرف نمی‌شود.
- Worker هر ۸ ساعت یک درخواست واقعی به پایگاه داده می‌فرستد تا ریسک توقف پروژه رایگان Supabase بر اثر بی‌فعالیتی کاهش یابد؛ تضمین قطعیِ عدم توقف از طرف Supabase وجود ندارد.

## انتشار در Cloudflare
در Cloudflare Dashboard:
1. وارد **Workers & Pages** شوید و **Create application → Connect to Git** را انتخاب کنید.
2. مخزن \`hamedbenapart69-byte/PadnaKesht-Telegram-Store\` را وصل کنید.
3. شاخه \`website-storefront\` را انتخاب کنید.
4. Root directory را \`website\` قرار دهید.
5. Build command را خالی بگذارید و Deploy command را \`npx wrangler deploy\` قرار دهید.
6. پروژه را Deploy کنید. فایل \`wrangler.toml\` تنظیمات Worker، فایل‌های سایت و Cron Trigger را تعریف می‌کند.

پس از انتشار، آدرس \`workers.dev\` در صفحه Worker نمایش داده می‌شود. اتصال دامنه اختصاصی را می‌توان بعد از تأیید نسخه منتشرشده انجام داد.

## پایگاه داده و API
- پروژه Supabase موجود پادناکِشت استفاده می‌شود؛ پروژه جدید یا طرح پولی ساخته نشده است.
- Edge Function با نام \`store-api\` فعال است و سورس آن در \`supabase/functions/store-api\` نگهداری می‌شود.
- جدول‌های سفارش و محصول RLS فعال دارند و دسترسی عمومی مستقیم ندارند؛ درخواست‌ها از Edge Function با نقش سرویس انجام می‌شوند.
- فایل migration در \`supabase/migrations\` نگهداری می‌شود.
- \`SUPABASE_URL\` و کلید publishable در \`wrangler.toml\` قرار دارند؛ کلید service-role و گذرواژه مدیر در مخزن قرار نمی‌گیرند. پس از ساخت Worker، در Settings → Variables and Secrets یک Secret با نام `STORE_PROXY_SECRET` اضافه کنید؛ مقدار آن را در مرحله تحویل دریافت می‌کنید. بدون این Secret، API عمداً درخواست‌ها را رد می‌کند.

## راه‌اندازی پنل مدیر
1. پس از انتشار سایت، مسیر \`/admin.html\` را باز کنید.
2. کد یک‌بارمصرف راه‌اندازی را وارد کنید.
3. گذرواژه شخصی با حداقل ۱۲ نویسه بسازید.
4. کد یک‌بارمصرف پس از استفاده باطل می‌شود.

## قیمت، موجودی و سفارش
- قیمت‌های تاریخی موجود در پایگاه داده تا زمان تأیید مدیر نمایش داده نمی‌شوند.
- موجودی‌های قدیمی نیز تأییدنشده محسوب می‌شوند و در سایت به‌عنوان موجودی قطعی نمایش داده نمی‌شوند.
- مدیر باید قیمت روز و موجودی واقعی هر کالا را در پنل ثبت کند.
- مشتری درخواست خرید را ثبت می‌کند؛ مبلغ نهایی و هزینه ارسال قبل از تأیید نهایی مشخص می‌شود.
- تأیید سفارش، موجودی را به‌صورت تراکنشی رزرو می‌کند. لغو سفارش پیش از ارسال، موجودی رزروشده را برمی‌گرداند.
- پرداخت اینترنتی در این نسخه وجود ندارد و هیچ درگاه یا حساب بانکی به سایت متصل نشده است.

## تصاویر
عکس‌های فعلی از Pexels و صرفاً نمایشی‌اند؛ عکس اختصاصی محصولات یا بسته‌بندی پادناکِشت نیستند. اعتبار تصاویر در \`/credits.html\` درج شده است. اگر دسترسی به دامنه تصاویر در ایران مختل بود، باید فایل‌های واقعی به فضای میزبانی خود Cloudflare منتقل شوند.

## کنترل کیفیت
Workflow شاخه \`website-storefront\` بررسی syntax جاوااسکریپت، TypeScript تابع Supabase، ساختار فایل‌ها و پیکربندی Wrangler را قبل از انتشار بررسی می‌کند.
