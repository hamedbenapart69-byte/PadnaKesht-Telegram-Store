# فروشگاه اینترنتی پادناکِشت

فروشگاه فارسی و راست‌چین با فهرست محصولات، سبد خرید، ثبت درخواست سفارش، پیگیری سفارش و پنل مدیریت.

## زیرساخت
- Cloudflare Workers و Static Assets برای میزبانی سایت و پراکسی API
- پروژه Supabase Free موجود برای دیتابیس و Edge Function
- GitHub برای نگهداری سورس و کنترل کیفیت پیش از انتشار
- بدون اعتبار هوش مصنوعی، بدون سرویس پولی و بدون درگاه پرداخت

Worker هر ۸ ساعت یک درخواست واقعی به دیتابیس می‌فرستد تا ریسک توقف پروژه رایگان Supabase بر اثر بی‌فعالیتی کاهش یابد. این راهکار تضمین قطعی عدم توقف از طرف Supabase نیست.

## انتشار در Cloudflare
در Cloudflare Dashboard:
1. وارد Workers & Pages شوید و Create application را بزنید.
2. GitHub را انتخاب و مخزن hamedbenapart69-byte/PadnaKesht-Telegram-Store را متصل کنید.
3. نام Worker را دقیقاً padnakasht-store قرار دهید تا با نام Wrangler یکسان باشد.
4. شاخه تولید را website-release انتخاب کنید. این شاخه فقط پس از موفقیت آزمون ساخت و ۱۰ بازبینی مستقل به‌روزرسانی می‌شود.
5. Root directory را website قرار دهید.
6. Build command:
   node --check src/index.js && node --check public/app.js && node --check public/admin.js && npx --yes wrangler@4 deploy --dry-run --outdir /tmp/padnakasht-worker
7. Deploy command:
   npx --yes wrangler@4 deploy
8. Save and Deploy را بزنید.
9. پس از ساخت Worker به Settings → Variables and Secrets بروید و یک Secret با نام STORE_PROXY_SECRET بسازید. مقدار این Secret را در تحویل نهایی دریافت می‌کنید. بدون آن، API عمداً درخواست‌ها را رد می‌کند.

پس از انتشار، Cloudflare آدرس workers.dev را نمایش می‌دهد. اتصال دامنه اختصاصی مرحله بعدی است.

## پایگاه داده و API
- از پروژه Supabase موجود پادناکِشت استفاده می‌شود؛ پروژه جدید یا پلن پولی ساخته نشده است.
- Edge Function با نام store-api فعال است و سورس آن در supabase/functions/store-api نگهداری می‌شود.
- جدول‌های سفارش و محصول RLS فعال دارند و دسترسی عمومی مستقیم ندارند؛ درخواست‌ها از Edge Function با نقش سرویس انجام می‌شوند.
- فایل‌های migration در supabase/migrations نگهداری می‌شوند.
- SUPABASE_URL و کلید publishable در wrangler.toml هستند. کلید service-role و گذرواژه مدیر در مخزن قرار نمی‌گیرند.
- Worker از کوکی HttpOnly برای نشست مدیر استفاده می‌کند؛ گذرواژه با PBKDF2 هش می‌شود و درخواست‌های حساس محدودسازی نرخ دارند.

## راه‌اندازی پنل مدیر
1. پس از انتشار سایت، مسیر /admin.html را باز کنید.
2. کد یک‌بارمصرف راه‌اندازی را وارد کنید.
3. گذرواژه شخصی با حداقل ۱۲ نویسه بسازید.
4. کد یک‌بارمصرف پس از استفاده باطل می‌شود.

## قیمت، موجودی و سفارش
- قیمت‌های تاریخی موجود در دیتابیس تا زمان تأیید مدیر به مشتری نمایش داده نمی‌شوند.
- موجودی‌های قدیمی نیز تأییدنشده‌اند و به‌عنوان موجودی قطعی نمایش داده نمی‌شوند.
- مدیر باید قیمت روز و موجودی واقعی هر کالا را در پنل ثبت کند.
- مشتری درخواست خرید را ثبت می‌کند؛ مبلغ نهایی و هزینه ارسال پیش از تأیید نهایی مشخص می‌شود.
- تأیید سفارش، موجودی را به‌صورت تراکنشی رزرو می‌کند. لغو سفارش پیش از ارسال، موجودی رزروشده را برمی‌گرداند.
- پرداخت اینترنتی در این نسخه وجود ندارد.

## تصاویر
تصاویر فعلی از Pexels و صرفاً نمایشی‌اند؛ عکس اختصاصی محصولات، بسته‌بندی یا تولیدکنندگان پادناکِشت نیستند. اعتبار تصاویر در /credits.html درج شده است. اگر دامنه تصاویر در ایران باز نشود، باید فایل‌های واقعی روی فضای میزبانی Cloudflare قرار بگیرند.

## کنترل کیفیت
GitHub Actions یک مرحله ساخت، بررسی TypeScript و Wrangler dry-run اجرا می‌کند. سپس ۱۰ Job مستقل معماری، امنیت، پایگاه داده، سفارش، موجودی، دسترس‌پذیری، واکنش‌گرایی، تصاویر، عملکرد و استقرار را بررسی می‌کنند. فقط پس از موفقیت همه مراحل، شاخه website-release به‌روزرسانی می‌شود.
